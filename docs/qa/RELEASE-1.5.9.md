## Fixes (Tester 1.5.8)
- **F158-3 (Medium) – Firebase: unlimited phoneIndex / users reads.** Phone numbers (and position / city) moved out of the public `users/{uid}` doc into `users/{uid}/private/profile` (owner-only); push tokens in `pushTokens/{uid}` (owner-only). A by-phone lookup reads `phoneIndex/{phone}` only after the account wrote a `lookups` counter: at most 60 lookups per hour per account (rules-enforced, plus a client throttle). The client (firebaseBackend, firebaseProfileDocs) reads and writes the new docs and never writes the legacy keys. Migration for existing users: scripts/admin/migrate-private-profiles.js (dry run by default; emulator + demo- project unless `--real-project <same id>` is given with no emulator set; never prints phones or tokens; idempotent; an existing private doc is never overwritten; docs with no phone are skipped and listed). **Limit: Firestore rules cannot count per IP** – the per-IP backstop exists on the API backend only. Product call (in DEPLOY): position / city are now private on Firebase (they were public before).
- **F158-1 (Low) – deciding-set points 1–4 accepted.** The deciding set now needs 5–99 points like the other sets: API 400 (ruleSetSchema) and firestore.rules (rulesOk). The app's picker only offers 11 / 15 / 21 / 25.
- **F158-2 (Low) – team-invite pendingPhones as a registered-number oracle (API).** Invites to registered and unregistered numbers get the same 200 and the same response shape (unregistered numbers are stored as pending). Each newly added invite number takes from the same per-user bucket as by-phone lookups (429 + Retry-After, the invite is not stored) and the per-IP backstop; re-saving the same pending list is free. Test / audit simulations lift the named limits through a test-only `liftNamed` flag (RateLimiter), never set by the app.
- **F158-4 (Info) – the icon glow note.** Corrected in RELEASE-1.5.8 (blockquote before "Fixes"): the faint glow reaches about 38.5 dp (past the 36 dp mask, ~581 near-transparent px clipped); the solid art stays within 33 dp; the adaptive background is a radial gradient around #0055A4. No build change.
- **F158-5 (Low) – "how many timeouts?" got the team-size FAQ.** New FAQ "score-timeouts" (EN/HI: 2 per set in Indoor, 1 with Beach, as the presets), HI / Hinglish synonyms (टाइमआउट, टाइम आउट, time-outs) and timeouts tags on the rule. Seven phrasings return the timeouts FAQ first, then the rule. Ask eval set docs/qa/ask-eval-1.5.9.jsonl = 1.5.8 set + 6 items (f1585-01..06).
- **F158-6 (Low) – mkzip misses.** Arithmetic ports ((a op b), ${…}, NAME = a op b), %-format / .format, str(N), YAML / JSON split host + port keys (within 4 lines), ports with a leading zero (04100) and `.flaskenv`-style env files (any `.…env` name except .venv) are refused. Also faster (fold() cached, ASCII fast path, Cf removal per distinct character – same result): a real-tree run takes about 6 s. test_mkzip: 161 refusal plants + allowed / quiet-skip files, all passed (about 22 min on the box).
- **V1426-3 (Low) – Firestore fixture lock: not fixable in rules (documented, still open).** The fixture lock, fixture_taken / not_ready and the claim checks need reads of the tournament, its fixtures and the match; together with the existing team / phone lookups they exceed the rules' per-request get()/exists() budget (and rules cannot query). The API backend (production) enforces them; the fixture list size cap from 1.5.8 stays.
- **TRUST_PROXY** is already "1" in render.yaml (the per-IP limits see the client address behind Render's proxy); nothing changed.

## Steering items (F158-7 to F158-13, daily quote)
- **F158-7 – web boot screen.** public/index.html reads the saved theme (volleylive.theme.v1: device setting, else the single signed-in user's, else auto 06:00–18:00 local = Day) before the bundle loads, sets the page background and theme-color, and shows the logo (public/boot-logo.png, a 192 px copy of assets/splash-icon.png – a web file, not an app icon, so no icon previews were regenerated). ThemeProvider starts from the same theme on web and shows the same logo until ready, so there is no flash. **Android:** the native splash follows the OS dark / light setting (expo-splash-screen #FFFAF3 / dark #1E2A44), not the in-app theme – the app's saved setting is not readable before the native splash.
- **F158-8 – Space toggles the checkbox.** New shared src/components/Checkbox (role checkbox, aria-checked, Space on web without page scroll, held key ignored, accessibility 'activate'); the Terms screen uses it. It is the only checkbox in the app (test).
- **F158-9 – browser Back on New Match.** Each step of /match/new is a same-URL browser history entry (src/hooks/useWebStepHistory): Back goes to the previous step, Forward returns, jumping back via the step dots goes to the matching entry, and the steps are unwound before the new match opens (so Back from the match does not return to a half-filled form). Native is unchanged.
- **F158-10 – "Pinned location" in Hindi.** Place labels on match / tournament cards, the match, tournament and court pages, the map and Home go through placeLabelT (EN "Pinned location", HI "पिन की गई जगह").
- **F158-11 – admin review: played matches only.** The list (API, demo, Firebase) shows finished matches needing review, abandoned matches, and live matches with an abandon request; scheduled matches are never listed. Approve / void buttons only on finished matches; the API answers 409 not_completed for approve / void on a scheduled or live match.
- **F158-12 – "8/6 starters".** A team has at most 6 starters (members not in subs): API 403 "At most 6 starters…", demo and firestore.rules (startersOf); a team already over 6 (older data) can still be edited if the change adds no starter. The demo Giants (8 players) now have 2 subs; the team page shows "N starters (max 6) · M subs – move K to subs" when over.
- **F158-13 – signed-in theme change vs the device default: unchanged (open product call).** It is the documented 1.4.22 behaviour (RELEASE-1.4.22, V1421-3: "A signed-in write never touches the device-wide default"), and the 1.4.22 test asserts it. Akshit to decide whether that should change.
- **Daily quote.** In Day the "Tap for next" words now also show the next item (they were outside the card's button); they are not a second screen-reader stop. Rotation: each tap shows the next item of the deterministic IST-day cycle; it wraps after the last item and resets to the day's item at IST midnight.
